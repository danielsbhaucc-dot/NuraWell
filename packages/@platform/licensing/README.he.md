# רישוי מודולים (@platform/licensing)

## מה זה עושה
נותן לכל מודול שנמכר רישיון חתום. הבסיס עובד **בלי שום שרת**: הקונה מקבל קובץ רישיון, והמודול בודק אותו אצלו עם מפתח ציבורי שמוטמע בחבילה. אם רוצים, אפשר להפעיל למודול מסוים גם **שרת אימות מקוון**, שרץ בלי שינוי על כל אחסון.

### שתי דרכי מכירה
- **חבילה (bundle), ברירת המחדל.** הקוד מכווץ ומעורפל, לכל קובץ יש טביעת אצבע במניפסט חתום, ולכל קונה יש סימן מים בלתי נראה. הרישיון קשור לדומיינים ותקף ל-30 יום. חידוש הוא רישיון חדש עם אותו מזהה.
- **קוד מלא (source).** הקונה מקבל את כל הקוד. אפשר לתת רישיון בלי תפוגה. אחרי זה אין לנו שליטה טכנית, רק התנאים המשפטיים.

### מה קורה אצל הקונה
1. הקונה מקבל קובץ `.tgz` עם הקוד, `LICENSE.token`, `license-public-key.pem`, `license.config.json`, תנאי הרישיון ו-`INTEGRITY.json`.
2. הכול רץ **על השרתים של הקונה**. מפתחות ההצפנה של המידע שלו נוצרים אצלו, ואנחנו לא מקבלים אליהם גישה.
3. בכל הפעלה המודול בודק: חתימה, תפוגה, מודול וגרסה, דומיין, ושלמות הקבצים.
4. אם הוגדר `revocationUrl`, המודול מוריד כל כמה שעות (ברירת מחדל 6) רשימת חסימות חתומה מקובץ סטטי. רשימה מזויפת לא נחשבת, וגם לא רשימה עם מספר גרסה נמוך מזה שכבר נראה.
5. אם הרשימה לא זמינה, המודול ממשיך לעבוד עד שהרישיון פג. התפוגה היא הבלם האחרון.
6. מודול נעול מציג הודעה נקייה בעברית (אפשר לשנות אותה) ולא מפיל את האפליקציה.

### מצבי חסימה
- `suspended_until`: השעיה עד תאריך. אחרי התאריך המודול חוזר לעבוד לבד.
- `suspended_until_payment`: השעיה עד שמחזירים את הרישיון לפעולה.
- `revoked_permanent`: ביטול לצמיתות.

הסיבה נשמרת מוצפנת (enc:v2) רק במסד שלנו. ברשימה הציבורית יש רק מזהה רישיון, מצב ותאריך. **אין מחיקה מרחוק של קבצים אצל הקונה.**

## שרת אימות מקוון (אופציונלי, לכל מודול בנפרד)
כשמפעילים אותו למודול, הוא נותן:
- **בדיקת ביטול מיידית**, בלי לחכות לרשימה הבאה (ברירת מחדל: מטמון של 60 שניות).
- **קשירה לדומיין**: השרת בודק שהדומיין שמדווח מופיע ברישיון, ושומר באילו דומיינים הרישיון נראה.
- **server-core (אופציונלי)**: פונקציות קטנות שרצות אצלנו רק לרישיון תקף. הפרוטוקול מוכן, אבל אף מודול לא משתמש בזה עדיין. מודול שתלוי ב-server-core לא יעבוד כשהשרת לא זמין, ולכן זו החלטה למודול ספציפי בלבד.

**כשהשרת לא זמין**, המודול חוזר לרישיון המקומי עד שהוא פג. תשובה מזויפת (חתימה שגויה), תשובה ממוחזרת (nonce אחר) או תשובה ישנה נחשבות "לא זמין".

### נייד לכל אחסון: בחירה בערך אחד
השרת הוא פונקציה רגילה מסוג `(Request) => Promise<Response>` עם fetch, Request/Response ו-crypto.subtle בלבד, בלי API של Node. אותו קוד עובד בלי שינוי:

```ts
import { createVerifierHandler, toHost, signedListStorage } from '@platform/licensing/online';
const handler = createVerifierHandler({
  licensePublicKeyPem: LICENSE_PUBLIC_KEY,     // ציבורי
  verifierPrivateKeyPem: VERIFIER_PRIVATE_KEY, // מפתח נפרד, מהסביבה של האחסון בלבד
  storage: signedListStorage(() => fetch(REVOCATION_URL).then((r) => r.json())),
  modules: { 'my-module': { enabled: true } },
});
// HOST = 'cloudflare' | 'vercel' | 'node'
export default toHost('cloudflare', handler);          // Cloudflare Workers
// export const POST = toHost('vercel', handler);       // Vercel route handler
// await toHost('node', handler).listen(8787);          // שרת משלכם (VPS)
```

אחסון השרת עובר דרך מתאם: `memoryStorage` (בדיקות), `kvStorage` (Cloudflare KV, Redis/Upstash וכו') או `signedListStorage`, שקורא את אותה רשימה חתומה שאנחנו מפרסמים, כך שיש מקור אמת אחד. **לא נוצר שום חשבון ולא הותקן שום שרת.** בחירת האחסון ממתינה להחלטה.

## התקנה
פקודה אחת ושדה הגדרה אחד:

```bash
node scripts/modules/install.mjs licensing --target <repo>
```

```json
{ "moduleId": "my-module", "licenseToken": "LICENSE.token", "revocationUrl": null, "pollHours": 6 }
```

השדה הנחוץ היחיד הוא הרישיון (`licenseToken`). כל השאר אופציונלי.

## הגדרות
| שדה | ברירת מחדל | מה זה |
|---|---|---|
| `moduleId` | – | מזהה המודול. חייב להתאים לרישיון. |
| `version` | – | הגרסה המותקנת. חייבת להיות בטווח של הרישיון. |
| `publicKeyPem` | – | המפתח הציבורי שמגיע בחבילה. |
| `licenseToken` | – | הרישיון. בלעדיו המודול נעול. |
| `host` | – | הדומיין של ההתקנה. |
| `instance` | – | טביעת אצבע של ההתקנה, אם הרישיון קשור אליה. |
| `revocationUrl` | אין | כתובת קובץ החסימות הסטטי. |
| `pollHours` | 6 | כל כמה שעות בודקים את הרשימה. |
| `cache` | בזיכרון | שמירת הרשימה האחרונה והגרסה הגבוהה ביותר. |
| `integrityOk` | – | תוצאת `verifyBundle` בזמן העלייה. |
| `lockedMessage` | "הרכיב הזה נעול כרגע…" | ההודעה שמוצגת כשהמודול נעול. |
| `online.enabled` | false | הפעלת שרת האימות למודול. |
| `online.url` | – | כתובת שרת האימות. |
| `online.verifierPublicKeyPem` | – | המפתח הציבורי של שרת האימות. |
| `online.cacheSeconds` | 60 | כמה זמן תשובה מהשרת נשמרת. |
| `online.timeoutMs` | 3000 | אחרי כמה זמן השרת נחשב לא זמין. |

## אבטחה ופרטיות
- מפתח ההנפקה (`LICENSE_SIGNING_KEY`) נקרא רק מהסביבה. הוא לא נמצא בריפו ולא בחבילה. בלי מפתח, המכירה והרישיונות כבויים עם הודעה ברורה.
- לשרת האימות יש מפתח נפרד. גם אם הוא דולף, אי אפשר להנפיק איתו רישיונות.
- ברישיון אין מידע אישי: רק מזהה לקוח שבחרנו, דומיינים ותאריכים.
- כל פעולה (הנפקה, חידוש, השעיה, ביטול, החזרה, פרסום) דורשת הרשאת modules.manage ואימות נוסף, ונרשמת ביומן בלי מידע אישי.

### הגנה בכנות
ההגנה המקומית מרתיעה העתקה ומקשה עליה, וסימן המים מאפשר לזהות מאיפה דלף עותק. **היא לא יכולה לעצור מי שמתעקש לפרק את הקוד**: כל קוד שרץ על מחשב של מישהו אחר אפשר לשנות בסוף. שרת האימות מוסיף שליטה מיידית, אבל רק server-core (קוד שלא נמצא אצל הקונה בכלל) נותן הגנה אמיתית, במחיר של תלות בשרת.

## מגבלות ידועות
- הכיווץ והערפול מוזרקים מכלי הבנייה. בשרת עצמו אין כיווץ, ולכן חבילה "חבילה" שנוצרת מהפאנל בלי כלי כזה יוצאת עם סימן מים ומניפסט, אבל לא מכווצת.
- server-core מתועד ולא מומש באף מודול.
- שרת האימות לא הותקן בשום מקום.
- תנאי הרישיון (`LICENSE-TERMS.he.md`) הם **טיוטה לבדיקה משפטית**.
