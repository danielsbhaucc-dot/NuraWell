2מה עושים לפי סוג התקלה

האתר לא עולה: ב-Vercel, במסך Deployments, בוחרים את הגרסה האחרונה שעבדה ולוחצים Promote to Production. זה חוזר לאוויר תוך דקה.
חשבון השרת נמחק או ננעל: יוצרים פרויקט Vercel חדש מאותו מאגר GitHub, ומעתיקים את כל משתני הסביבה. את המפתחות משחזרים לפי מדריך השחזור, ואת שאר המשתנים (מסד נתונים, מייל) מקבלים מחדש מהמסכים של כל שירות. בסוף מכוונים את הדומיין ב-Cloudflare לפרויקט החדש.
מידע במסד הנתונים נמחק או השתבש: משחזרים מהגיבוי הלילי לפי סעיף 3 למטה (אם עוברים לתוכנית בתשלום, אפשר לשחזר גם במסך Database ואז Backups). לא משנים מפתחות, כי הם לא תלויים במסד.
חשד לפריצה: כותבים לגדעון "ניתוק מכל המכשירים" (או מנתקים את כל המשתמשים ב-Supabase, במסך Authentication). אחר כך מחליפים סיסמאות ב-GitHub, ב-Vercel, ב-Supabase וב-Cloudflare, ופונים לעורך הדין לגבי חובת דיווח לרשות להגנת הפרטיות.
מפתחות ההצפנה אבדו: פותחים את "מדריך גיבוי ושחזור המפתחות" ופועלים לפי שלב 4.

3שחזור מסד הנתונים מהגיבוי הלילי

מה צריך: מחשב עם Postgres 17 ועם הכלי age, את מפתח פתיחת הגיבוי (נמצא בגיבוי המפתחות בשם DB_BACKUP_AGE_IDENTITY), ואת כתובת החיבור של מסד הנתונים שמשחזרים אליו.
  1. ב-Cloudflare, באחסון הקבצים R2, נכנסים לתיקייה backups/db/ ומורידים את הקובץ האחרון שמסתיים ב-.dump.age, ואת קובץ ה-.sha256 שלידו, לאותה תיקייה.
  2. שומרים את מפתח הפתיחה בקובץ identity.txt באותה תיקייה.
  3. אם מסד הנתונים נמחק לגמרי: פותחים פרויקט חדש ב-Supabase באירופה, ובמסך Connect מעתיקים את כתובת החיבור הישירה (Direct connection).
  4. מריצים מתיקיית הקוד:
    AGE_IDENTITY_FILE=identity.txt TARGET_DATABASE_URL='כתובת-החיבור' bash scripts/backup/db-restore.sh nurawell-db-….dump.age
    הפקודה בודקת קודם שהקובץ שלם (שורה שמסתיימת ב-OK), ורק אחר כך משחזרת.
  5. הודעות על דברים "שכבר קיימים" בפרויקט Supabase חדש הן תקינות. בודקים במסך Table Editor שיש משתמשים והודעות.
  6. בפרויקט חדש: מעדכנים ב-Vercel את משתני הסביבה של Supabase (כתובת ומפתחות) ומעלים מחדש. מפתחות ההצפנה לא משתנים, ולכן המידע המוצפן נפתח כרגיל.
  7. מוחקים את identity.txt מהמחשב בסיום.
