**בעל אירוע:** דניאל רחמן. **יעד:** בלימה תוך שעה, הערכה תוך 24 שעות.

## 0. זיהוי
מקורות: התראות ops_security_events, GitHub secret scanning, gitleaks/TruffleHog, Snyk, דיווח משתמש, חיובים חריגים (Vercel/AI/Supabase).

## 1. בלימה (שעה ראשונה) — לפי סוג
| אירוע | פעולה מיידית |
|---|---|
| סוד דלף (מפתח API/DB) | סובב ב-Vercel/Supabase/ספק → Redeploy → בדוק לוגים לשימוש. מפתח Supabase service role: Dashboard → API → rotate |
| חשבון אדמין נפרץ | ביטול passkeys, `auth.admin.signOut` לכל הסשנים, סיבוב סודות ops |
| חשבון GitHub/Vercel/Google נפרץ | שינוי סיסמה + 2FA, ביטול טוקנים/OAuth apps, בדיקת audit log |
| דליפת נתונים/IDOR | השבתת הנתיב (feature flag/revert PR), שמירת ראיות |
| כופרה/מחיקה | **לא** לשחזר לפרוד לפני הבנה; שחזור לסביבה נפרדת (BACKUP_RESTORE_TEST) |
| ספק נפרץ (supply chain) | נעילת גרסה, revert, סיבוב סודות שהיו חשופים ל-CI |

## 3. הערכה (עד 24 שעות)

## 4. דיווח — "אירוע אבטחה חמור" (תקנה 11)
- מידע רגיש שנחשף/דלף → **דיווח מיידי לרשות להגנת הפרטיות** (טופס מקוון באתר הרשות), כולל צעדים שננקטו.
- הרשות רשאית להורות על **הודעה לנושאי המידע**. מומלץ להודיע ביוזמה כשיש סיכון ממשי.
- תבנית הודעה למשתמשים: מה קרה, מתי, אילו נתונים, מה עשינו, מה מומלץ לך, איש קשר.
- לערב עו"ד לפני הודעה פומבית.

## 5. התאוששות ולקחים
