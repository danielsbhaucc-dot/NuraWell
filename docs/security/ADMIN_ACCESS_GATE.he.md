# שער גישה לניהול — מדריך הפעלה

## דגלים (Vercel env, ברירת מחדל: כבוי)
- `OPS_ENROLL_ONLY=on` — מכשיר שלא נרשם מקבל 404 גנרי בכל נתיבי הניהול. כניסות מכשירים לא רשומים נספרות (`ops_probe_hit`) ונכנסות לביקורת הלילית.
- `OPS_ADMIN_HOST_ONLY=on` — ממשק הניהול זמין רק בתת-הדומיין הקנוני. מוכן אך לא מחובר; אין שינויי DNS.

## רישום מכשיר חדש
1. דניאל שולח לגדעון "מכשיר חדש" או `/newdevice` (רק מזהה הטלגרם המאומת; אחרים — מתעלמים בשקט).
2. גדעון מחזיר קישור חד-פעמי (`/k/<token>`), תקף 10 דקות; נשמר רק hash. עד 3 קישורים ב-10 דקות.
3. הקישור לבד לא רושם: פתיחה (תפיסה אטומית) → סיסמה + גורם חזק קיים (קוד גיבוי / passkey / מפתח חומרה).
4. התאמת מספר: המכשיר מציג מספר, גדעון שולח 3 כפתורים. מספר שגוי = דחייה, ביטול הקישור, התראה וחסימת IP ל-30 דק'.
5. רישום passkey (אימות משתמש חובה) → עוגיית מכשיר. נשלחת הודעת טלגרם עם כפתור "בטלו".

## ביטול
- כפתור הביטול בטלגרם או מסך "מכשירים" — מבטל את המכשיר ומנתק את כל הסשנים של אותו מנהל.

## Break-glass
- שחזור דרך כלי גדעון (סבב סיסמה) — לא חסום ע"י השער.

## גישה למידע אישי
- כל צפייה בפרטי משתמש דורשת נימוק (15 תווים לפחות, כרטיס אופציונלי), מאשרת 30 דקות למשתמש אחד, ונרשמת ביומן append-only.

## ביקורת לילית
- סינון מקדים ב-DB; קריאה למודל זול רק כשיש חריגות, עם מזהים פסאודונימיים בלבד. ממצאים בינוני/גבוה → התראה לגדעון ומסך האבטחה.

## Cloudflare Zero Trust (אופציונלי, חינם עד 50 משתמשים)
1. Zero Trust → Access → Applications → Self-hosted, דומיין הניהול בלבד.
2. מדיניות Allow: אימייל של המנהלים + One-time PIN / IdP.
3. Device posture (WARP) — אופציונלי.
4. לא לשנות DNS לפני בדיקה מול proxied record; אפשר לחזור אחורה ע"י מחיקת האפליקציה.

## חזרה אחורה
- כיבוי הדגלים מחזיר את ההתנהגות הקודמת. המיגרציות 000198–000200 תוספתיות בלבד.

## עדכון: חיבורים לפי מכשיר, ביקורת וממצאים (000201)

- **כל חיבור ניהול קשור למכשיר אחד, וחיבור לא קשור נדחה.** הקישור (`ops_admin_sessions`) נוצר רק בכניסה מלאה (סיסמה + גורם נוסף, או פאסקי/קוד גיבוי) ממכשיר רשום, ב-15 הדקות שאחרי הכניסה. חיבור ישן שלא נקשר אף פעם לא "מאומץ" מאוחר יותר: המערכת מנתקת אותו ומבקשת להתחבר מחדש. מאז הוא מתקבל רק מאותו מכשיר (או מהמכשיר המקושר אליו במעבר בין האתרים). הבדיקה רצה בכל בקשה ל-Ops ולכל API ניהולי, ואם היא נכשלת הגישה נחסמת. כשהדגל `OPS_ENROLL_ONLY` כבוי, כניסה רגילה ממכשיר מאושר יוצרת את הקישור, כך שאי אפשר להינעל בחוץ.
- **ביטול מכשיר** מנתק מיד רק את החיבורים של אותו מכשיר. מכשירים אחרים ממשיכים לעבוד.
- **"ניתוק כל החיבורים"** הוא פעולה נפרדת: כל החיבורים בכל המכשירים מתנתקים, והמכשירים נשארים רשומים.
- **מעקב מכשיר:** בכל בקשה מאומתת מתעדכנים IP (מוסתר), מדינה ודפדפן, לכל היותר פעם ב-5 דקות. כשמכשיר מוכר מגיע ממדינה חדשה, גדעון שולח התראה עם כפתור ביטול.
- **ממצאי הביקורת הלילית:** ממצא פתוח אפשר לסמן כ"נבדק". המערכת שומרת מי סימן ומתי, ורושמת את הפעולה ביומן הניהול. אם הרישום ביומן נכשל, הסימון מבוטל.
- **שער מידע אישי:** גם מסכי הזיכרון, אלמוג, הייצוא, יומני הפלטפורמה, הבדיקה המקדימה והאימות המשפטי דורשים סיבה מתועדת. האכיפה בשרת.
